# 即時計分板（四隊）— 線上版

手機在台下統計 → 舞台大螢幕即時顯示。純靜態網頁（GitHub Pages），即時同步用 Supabase Realtime 廣播，**不需要伺服器、不需要帳號、0 元**。

## 兩頁

| 網址 | 用途 |
|---|---|
| `index.html` | 首頁，兩個入口 |
| `board.html` | 舞台大螢幕（唯讀）：超大字分數、名次、領先高光、卡牌橫幅、QR。按 **F**（mac/Linux）或 **F11**（Windows）全螢幕 |
| `pad.html` | 手機控制台：加減分、卡牌算式、改隊名、復原、鎖定、操作紀錄 |

## 房間代碼

兩頁靠網址結尾的 `#r=房間代碼` 配對，例如：

```
board.html#r=myevent-2026
pad.html#r=myevent-2026
```

- 不給就落在預設房間（適合測試）
- **代碼只在網址裡，不在這個 repo 裡**，所以不會被搜到
- 大螢幕右下的 QR 就是「這一頁的網址換成 pad.html」，房間自動帶著走 → 手機掃了直接進同一個房間

## 資料在哪裡

- **分數存在操作的那支手機**（`localStorage`）。關掉瀏覽器、重開機都還在
- 手機每 2 秒廣播一次目前狀態；大螢幕剛開或重連時會主動「打招呼」，控制台立刻重播
- 大螢幕不保存任何東西：重新整理後會等控制台的下一次廣播（最多 2 秒）
- 換一支手機當控制台 = 從 0 開始（原本那支手機仍握有自己的一份）

## 已知限制

- 只適合「一台手機操作、一台大螢幕顯示」。兩支手機同時操作會互相覆蓋（最後寫入者贏）
- 需要對外網路（會場 Wi-Fi 若要網頁認證，先認證再開）
- 沒有身份驗證：任何拿到「房間代碼 + 網址」的人都能操作控制台。房間代碼請當密碼用
- 廣播是即時通道、不是資料庫，服務端不留紀錄

## 技術

- 靜態頁面：GitHub Pages
- 即時同步：Supabase Realtime Broadcast（publishable key，前端可用；不需要資料表）
- QR：`vendor/qrcode.js`（MIT）瀏覽器端產生
- 卡牌算式（吸取、減半、平均、首尾對調、全場吸取、平分、互換）在瀏覽器內計算，算式與本機版 `server.py` 完全一致

## 本機開發

```bash
python3 -m http.server 8100      # 在這個資料夾
# 大螢幕 http://127.0.0.1:8100/board.html#r=dev
# 手機台 http://127.0.0.1:8100/pad.html#r=dev
```
